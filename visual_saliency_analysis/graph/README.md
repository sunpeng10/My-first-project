## 一、当前网络具备哪些数据

| 数据类型 | 是否具备 | 来源 | 可靠性 |
|----------|:--------:|------|:------:|
| **微博节点** | ✅ 500 条 | `weibo_metadata.csv` | 高 |
| **作者 UID（source node）** | ✅ 403 个唯一 | 从 `weibo_url` 正则提取 `weibo.com/{UID}/` | **高（500/500 提取成功，0 失败，0 异常）** |
| **@提及关系（mention edge）** | ⚠️ 半具备 | 从 `text` 正则提取 `@用户名` | 中（见下文） |
| **用户名 → UID 映射** | ❌ 无 | — | 无法建立 |

### 关键结论

- **作者 UID 可可靠提取**：500 条微博全部含标准 `weibo_url`，正则提取 `author_uid` 成功 500/500，无异常 URL。
- **@提及可提取为“用户名字符串”，但无法解析成 UID**：`text` 中的 `@用户名` 是自由文本，数据里既没有作者的用户名字段，也没有官方的 username→uid 索引。

## 二、哪些关系可以直接用于建图

### ✅ 可直接建图：mention 关系（第一版）

当前可以构建**有向边**：

```
source_uid  ──mention──▶  mentioned_username(字符串)
```

- `source_uid`：发微博并作出 @提及 的作者 UID（可靠）。
- `mentioned_username`：被 @ 的用户名（字符串，**未解析为 UID**）。

规模：44 条微博含 @提及，共 61 次提及，去重后 53 个被提及用户名。

⚠️ **局限**：这是一个「UID 节点 → 用户名字符串节点」的半开放图，两类节点无法闭合对齐。因为 `mentioned_username` 无法映射回 UID，所以：

- 无法合并“被提及者”的多个用户名变体；
- 无法判断被提及者是否就是本数据集的某位作者；
- 无法做 UID→UID 级别的传播/影响力分析。

### ✅ 可直接统计：作者发帖分布

`post_authors.csv` 已给出 403 个唯一作者及其发帖数，可做作者层面的描述性统计（不依赖用户名）。

## 四、为什么 shares / comments 不能直接当作 Edge

`shares` 和 `comments` 是**聚合计数**（某条微博被转发/评论的总次数），不是关系结构：

1. **没有端点信息**：计数只告诉你“发生了 N 次转发”，但不知道“谁转发”、也不知道“转发/评论指向谁”。
2. **不是节点对**：一条网络边必须形如 `(source, target)`，而 `shares=191` 只是一个标量，无法还原成 191 条 `(用户X → 用户Y)` 的边。
3. **会造成伪边**：若强行把 `shares` 当作边，等于凭空假设“作者 → 191 个不存在的节点”，属于**人工制造传播关系**，违反本阶段约束。

因此本阶段**未**把 `shares` / `comments` 转成任何 Edge。

## 五、下一步需要补采集什么数据

要使传播网络达到可训练/可分析的状态，按优先级：

1. **【最高】用户名 → UID 映射**：对 53 个被提及用户名（以及 403 个作者）补采 `user_name → uid` 对照表。方法：
   - 采集时在解析器里**新增 `user_name` 字段**（DOM 里 `.name` 元素），与 `weibo_url` 的 uid 一并落库；
   - 或用微博 API 按用户名/主页 URL 反查 uid（需登录态）。
   - **在拿到官方映射前，严禁猜测或伪造 UID。**

2. **转发/评论关系边**：若需做真正的传播级联分析，需重新采集每条微博的**转发列表**（谁转发了）和**评论列表**（谁评论了、回复了谁），而非仅计数。这需要扩展 `D:\WeiboCrawler` 爬虫（新增进入微博详情页抓取 `forward`/`comment` 列表的逻辑）。

3. **（可选）补充作者节点属性**：粉丝数、认证类型等，用于后续节点特征。

> 建议顺序：先完成第 1 项（username→uid 映射），即可把当前半开放的 mention 图闭合为 `UID → UID` 的第一版正式 mention network；第 2 项决定能否构建 repost/comment 网络。
